## Before you begin

You must be, or be working with, an account servicing entity (ASE). An ASE is an entity that provides and maintains payment accounts for its customers and is regulated in the jurisdictions it operates. Examples of ASEs include banks, digital wallet providers, and mobile money providers. The [account servicing entity](/overview/concepts/account-servicing-entity) page provides examples of an ASE's responsibilities and obligations.

For testing purposes, you can set up a [mock account servicing entity](/integration/playground/overview) that's deployed Rhyza. However, Rhyza **should not** be used in production environments by non-regulated ASEs.

## Software components

Rhyza is a decoupled, event-driven system organized into multiple **bounded contexts**. Each context is composed of specialized services, including APIs, domain logic, and event-driven command/event handlers that communicate via Kafka.

### Bounded contexts

<CardGrid>
  <Card title="Payments">
    Stores, initiates, and receives payments. Includes services for payment
    intent lifecycle, quoting, and payments.
  </Card>
  <Card title="PAL (Peers, Accounts, and Liquidity)">
    Manages assets, wallet addresses, peers, and the core accounting ledger &
    liquidity.
  </Card>
  <Card title="ILP">
    Handles the Interledger Protocol (ILP) layer, routing packets between peers
    and managing connections.
  </Card>
  <Card title="Auth">
    Internal authorization services that manage Open Payments grants and access
    tokens.
  </Card>
  <Card title="Notifications">
    Processes system events and delivers webhooks to the ASE.
  </Card>
</CardGrid>

### Integration & Open Payments services

<Card title="Admin API Service" icon="setting">
  The unified REST interface used by the ASE for all administrative tasks,
  including managing assets, wallet addresses, and initiating payments. **This
  is the primary point of integration.**
  <p></p>
  <p>[Admin API Reference >](/apis/scalar/admin-api)</p>
</Card>

<CardGrid>
  <Card title="Open Payments Auth Server">
    Standalone service implementing the Open Payments authorization server
    specification. It must be deployed to handle authorization grants from
    external clients.
    <p></p>
    <p>[Learn more >](/overview/concepts/open-payments#open-payments-auth-server)</p>
  </Card>

  <Card title="Open Payments Resource Server">
    Standalone service that hosts and manages access to protected Open Payments
    resources. It must be deployed to expose wallet addresses and payment
    resources to the network.
    <p></p>
    <p>[Learn more >](/overview/concepts/open-payments#open-payments-resource-server)</p>
  </Card>
</CardGrid>

## Payments

The following steps illustrate how to make a basic payment between two wallet addresses on the same Rhyza instance.

<CardGrid>

<Card title="1. Create an incoming payment">
  {' '}
  Use the Admin API's `POST /payment-intents` to create an incoming payment
  resource on the recipient's wallet account.<p></p>
  <p>[Admin API Reference >](/apis/scalar/admin-api)</p>
</Card>

<Card title="2. Create a quote">
  {' '}
  Use the Admin API's `POST /quotes` to create a quote resource on the sender's
  wallet account. The quote shows how much it will cost the sender to deliver an
  amount to the receiver.<p></p>
  <p>[Admin API Reference >](/apis/scalar/admin-api)</p>
</Card>

<Card title="3. Create a payment">
  {' '}
  Use the Admin API's `POST /payments` to create a payment resource on the
  sender's wallet account. This operations starts the payment. At this point,
  the sender's ASE must fund/approve the payment before it sends.<p></p>
  <p>[Admin API Reference >](/apis/scalar/admin-api)</p>
</Card>

<Card title="Handle webhook requests">
  {' '}
  As the payment flow progresses, the ASE is be notified about events that
  happen in the system. Some events are actionable, such as an `payment.created`
  event. Review the webhook events page to learn more about handling each event.
  <p></p>
  <p>[Webhook events >](/integration/requirements/webhook-events)</p>
</Card>

</CardGrid>
