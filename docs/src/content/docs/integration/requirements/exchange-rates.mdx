If you plan to support cross-currency transactions, you must specify how Rhyza obtains exchange rates. Rhyza supports two models for handling exchange rates: Pull (Rhyza makes a request to an endpoint hosted by the ASE) and Push (the ASE sets the exchange rates via the Admin API directly).

A rate probe precedes every Interledger payment to provide a quote that estimates the full cost of transferring value. For cross-currency transactions, Rhyza needs the exchange rates for the currencies involved in the payment.

---

## Pull model

In the pull model, Rhyza requests exchange rates from the ASE whenever a rate is needed and not available in its local cache.

### Configure the pull model

To enable the pull model, you must configure the `EXCHANGE_RATES_URL` environment variable for the `pal-api-service`.

```bash title='Example'
EXCHANGE_RATES_URL: http://cloud-nine-wallet/rates
```

### Pull request specification

The configured endpoint must accept <Badge text="GET" variant="note" size="medium"/> requests. Rhyza will include the base asset code as a query parameter.

```bash title="Example API request"
GET https://cloud-nine-wallet/rates?base=USD
```

### Pull response specification

The endpoint must return a JSON response containing the base asset and a mapping of exchange rates for other supported assets.

```json title='Example API response'
{
  "base": "USD",
  "rates": {
    "EUR": 0.813399,
    "MXN": 17.05
  }
}
```

<div class="overflow-table">

| Field                | Type   | Description                                                                                                                               | Required |
| -------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| `base`               | String | The asset code represented as an <LinkOut href="https://en.wikipedia.org/wiki/ISO_4217">ISO 4217</LinkOut> currency code, for example USD | Y        |
| `rates`              | Object | Object containing `<asset_code : exchange_rate>` pairs                                                                                    | Y        |
| `rates.<asset_code>` | Number | The exchange rate relative to the `base` asset                                                                                            | Y        |

</div>

## Push model

In the push model, the ASE sets exchange rates in Rhyza directly via the Admin API, instead of having to host an external endpoint for Rhyza to query.

### Using the Admin API

Exchange rates are pushed to Rhyza by sending a <Badge text="POST" variant="note" size="medium"/> request to the `/rates` endpoint. Rates set via the push model are associated with a specific peer.

#### Set exchange rate request

```bash title="Example API request"
POST https://rhyza.example.com/rates
```

```json title="Example payload"
{
  "peerId": "480ef339-7842-4501-a905-923fc1339cef",
  "sourceAssetCode": "USD",
  "destinationAssetCode": "EUR",
  "rate": 0.92,
  "rateTtlSecs": 3600
}
```

<div class="overflow-table">

| Field                  | Type   | Description                                                               | Required |
| ---------------------- | ------ | ------------------------------------------------------------------------- | -------- |
| `peerId`               | String | The unique identifier of the peer these rates apply to.                   | Y        |
| `sourceAssetCode`      | String | The source currency code (e.g., "USD").                                   | Y        |
| `destinationAssetCode` | String | The destination currency code (e.g., "EUR").                              | Y        |
| `rate`                 | Number | The exchange rate from the source asset to the destination asset.         | Y        |
| `rateTtlSecs`          | Number | The time-to-live for this rate in seconds. If omitted, a default is used. | N        |

</div>

## Rate caching

For the Pull model, you can specify how long Rhyza caches exchange rates via the `EXCHANGE_RATES_LIFETIME_SECS` environment variable (default is `3600` seconds). Caching improves performance by reducing the number of outgoing requests to your rates endpoint.

For the Push model, the `rateTtlSecs` provided in the API request determines the lifetime of the specific rate. If a pushed rate is not available or has expired, Rhyza will attempt to pull the rate from the `EXCHANGE_RATES_URL` if configured. If the pull model is not configured or also fails to provide a rate, Rhyza will fail the payment or quote request with an error.

---

## Environment variables

The following variables are used by the `pal-api-service` to manage exchange rates.

<div class="overflow-table">

| Variable                       | Type   | Description                                                                    | Default |
| ------------------------------ | ------ | ------------------------------------------------------------------------------ | ------- |
| `EXCHANGE_RATES_URL`           | URL    | The external endpoint used for the Pull model.                                 | -       |
| `EXCHANGE_RATES_LIFETIME_SECS` | Number | The duration (in seconds) Rhyza caches pulled exchange rates.                  | `3600`  |
| `EXCHANGE_RATES_TIMEOUT_SECS`  | Number | The timeout (in seconds) Rhyza waits when pulling exchange rates from the ASE. | `10`    |

</div>
